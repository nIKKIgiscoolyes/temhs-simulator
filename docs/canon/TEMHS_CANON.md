# 5. CANON PRECEDENCE

TEMHS is an established fictional institution.

Do not continuously reinvent it.

Use the following authority hierarchy:

## AUTHORITY 1
Explicit new instructions from the user.

## AUTHORITY 2
Repository canon documents under:

`docs/canon/`

## AUTHORITY 3
This master development contract.

## AUTHORITY 4
Documented implementation defaults.

Implementation defaults are NOT automatically lore.

When a detail is not known but software requires a value, label it clearly:

`IMPLEMENTATION_DEFAULT`

Do not silently convert guessed values into official TEMHS history.

If an actual contradiction is discovered:

1. document it in `docs/CANON_CONFLICTS.md`;
2. preserve both established claims;
3. avoid designing a new lore explanation unless necessary;
4. continue working around the contradiction if possible.
